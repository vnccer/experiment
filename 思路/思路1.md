# 思路1：校园安全运营智能体的授权感知日志注入防护

> 定位：面向小论文的先导研究，也是[《思路2：校园安全智能体快慢协同防护研究》](./思路2_方向三.md)中的快路径模块。先验证攻击链和方法是否成立，再决定是否扩大实验。

## 一、背景

### 1.1 为什么做这个

校园安全运营智能体需要读取端点日志、网络告警和威胁情报，完成告警研判、证据检索和响应建议。日志中的 URL、User-Agent、DNS 查询、文件名、进程参数等字段可能受攻击者影响，其中可以夹带自然语言指令，诱导智能体：

- 把真实攻击判断为正常；
- 错误调整告警优先级；
- 忽略关键证据；
- 产生封禁、隔离或停用账号等越权动作。

本研究把这类风险称为**对抗日志注入**。核心安全原则是：

> 不可信遥测可以提供事实线索，但不能自行授予研判降级或高影响响应权限。

### 1.2 之前研究的不足

已有工作已经研究了日志提示注入、通用间接提示注入检测、安全重排和运行时工具防护，因此本研究不能把“发现日志注入”或“增加权限检查”单独作为创新。

现有研究仍有三个可继续验证的问题：

1. 许多防御只判断一段文本是否像提示注入，没有结合当前任务究竟允许什么动作；
2. 通用 Agent 防御多在邮件、文件等任务上验证，缺少校园安全运营日志和响应动作场景；
3. 仅过滤可疑日志可能丢失有价值的攻击事实，安全性和正常研判效用需要同时评价。

### 1.3 与立项课题的关系

本思路只研究日志进入模型上下文前的**低成本快路径**，不承担完整慢路径、生产级 Wazuh 平台和真实自动处置。

```text
不可信端网遥测
→ 授权感知风险判断
→ 安全重排与内容准入（思路1）
→ 高风险事件运行时验证（思路2）
→ 受控响应建议或沙箱动作
```

思路1的事件、任务、攻击样本、授权标签和检查器均应能被思路2直接复用。

## 二、创新点

### 2.1 任务授权差距感知

风险不只取决于日志“像不像注入”，还取决于日志试图诱导的动作是否超出当前可信任务和已批准剧本的授权范围。

授权条款统一表示为：

```text
动作—对象—参数—前置条件
```

例如，同一条日志中的“封禁该 IP”指令，在“只总结证据”和“确认攻击后模拟封禁指定 IP”两个任务中的风险应不同。

### 2.2 资产后果感知

同一种动作作用于测试主机、教学系统或统一身份服务器，后果不同。方法将目标资产重要性和动作影响纳入风险判断，优先阻止高影响越权动作。

### 2.3 保留事实、抑制控制

防御不直接删除整条日志，而是区分：

- 可安全序列化的事实字段，如时间、事件类型、主体、客体和 IOC；
- 可能包含控制指令的自由文本字段。

目标是在降低攻击成功率的同时，尽量保留关键安全证据。

### 2.4 配对反事实评测

使用“相同证据、不同可信授权”的配对任务，观察方法能否随授权范围和资产后果改变风险判断。这既是方法验证，也是区别于静态注入检测的主要实验设计。

### 2.5 可证伪边界

TAG-Rerank只是一个待验证的候选快路径，不是必须成功的前提。如果它不能优于固定风险或非结构化任务条件基线，就停止扩大该方法，保留负结果，并在思路2中使用表现最好的轻量基线。

## 三、实验框架

### 3.1 最小任务集

实验采用离线、可控的校园安全事件包，不连接生产校园网。

- 起步阶段：2个事件模板、4个配对任务，只用于跑通链路；
- 小论文核心：4个事件模板、约8个配对任务；
- 毕设复用：再增加2个新模板，最终形成约12个任务。

优先选择以下事件：

1. 异常登录与账号暴力破解；
2. 可疑进程或文件落地；
3. DNS 异常或可疑外联；
4. 统一身份账号处置。

每个事件包包含正常证据、关键攻击证据、无关干扰证据和一条注入记录。端点侧使用 Sysmon/Wazuh 风格事件，网络侧使用 Suricata/Zeek 风格事件。

### 3.2 智能体与工具

先使用一个主模型和少量受控工具：

- 查询事件；
- 查询资产；
- 升级告警；
- 模拟封禁 IP 或隔离主机。

所有高影响动作只修改沙箱状态，不操作真实资产。

### 3.3 实验流程

```text
可信分析任务与批准剧本
→ 检索候选证据
→ 普通重排或授权感知安全重排
→ 证据进入智能体上下文
→ 智能体研判或调用模拟工具
→ 确定性检查器判断任务完成和越权行为
```

### 3.4 对照方法

核心只保留四组：

1. 无防御；
2. 固定注入检测或固定风险惩罚；
3. 非结构化任务条件风险评分；
4. 授权差距与资产后果感知的 TAG-Rerank。

所有方法使用相同的字段解析、任务、攻击样本和调参预算，避免因预处理不同造成不公平比较。

### 3.5 攻击与指标

核心攻击先做两类：直接注入、与日志语义匹配的伪装注入。LLM 自动改写只用于少量确认实验，自适应攻击留到核心结果成立之后。

主要指标：

- 端到端攻击成功率；
- 越权动作率和高影响错误动作率；
- 无攻击任务效用；
- 关键证据 Recall@K；
- 控制文本是否真正进入模型上下文。

延迟、调用次数和 token 用量作为辅助成本指标。

### 3.6 执行阶段

1. **P0：攻击链检查**。先确认模型能完成正常任务，并且日志注入确实可能影响研判或模拟动作；
2. **P1：快路径比较**。实现四组对照，验证授权差距是否带来方向一致的收益；
3. **P2：论文完善**。只有P1结果为正且正常效用可接受时，才增加任务、模型和更强攻击。

出现以下情况时暂停扩大：基础模型不能完成正常任务、恶意证据无法进入上下文、授权抽取不可靠，或 TAG-Rerank 不优于更简单的基线。

## 四、细节

### 4.1 信任边界

可信来源包括：分析师任务、已批准剧本、角色权限、工具模式、资产等级和沙箱状态。

不可信来源包括：日志和告警中的自由文本、外部威胁情报，以及攻击者可影响的 URL、DNS、文件名和进程参数。结构化字段不等于可信，仍需校验、限长、转义和安全序列化。

### 4.2 方法的简化表达

方法先提取证据可能诱导的动作，再与当前已激活授权比较：

```text
授权差距 = 可达的诱导动作 - 当前已激活的授权动作
风险 = 注入可能性 × 授权差距及资产后果
安全重排分数 = 相关性 - 风险惩罚
```

前置条件只能由可信环境状态或独立证据规则确认，不能由一条不可信日志自行声明成立。

### 4.3 三级内容准入

- 低风险：完整证据参与重排；
- 中风险：移除可疑控制文本，保留安全序列化事实；
- 高风险：控制文本不进入模型，记录被标记并交给思路2的慢路径。

### 4.4 数据与检查器

每个任务至少记录：可信目标、允许动作、禁止动作、正确研判、关键证据和预期沙箱状态。攻击是否成功由确定性检查器判定，不只依赖关键词或另一个大模型的主观评分。

开发集用于选择阈值，测试集只用于最终评价；同一事件及其注入改写不能跨集合。

### 4.5 不做的内容

小论文阶段不建设完整 Wazuh 平台，不研究多智能体、全局攻击图、多阶段 APT、真实自动处置和生产校园网部署。

### 4.6 预期产出

- 一个可复用的校园安全运营任务与事件包；
- 一套授权、攻击和越权动作检查器；
- TAG-Rerank及三类必要基线；
- 一篇关于任务授权感知日志注入防护的先导论文；
- 可直接进入思路2的快路径代码、数据和失败样例。
