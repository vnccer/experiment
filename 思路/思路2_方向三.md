# 思路2：面向对抗日志注入的校园安全运营智能体快慢双路径防护

## 0. 选题定位

### 0.1 对应指南

- 指南大类：**方向三——面向 AI 驱动攻击的教育行业 AI 原生安全运营技术体系研究**。
- 主要对应参考课题：**资源受限条件下安全运营快慢双路径智能研判与响应机制研究**。
- 必须兑现的核心：资源受限条件下的快路径筛选、慢路径验证及二者的安全—效用—成本折中。
- 必须保留的场景证据：核心实验至少覆盖一种端点遥测和一种网络遥测，并完成至少一个受控端网事件的联合研判；若未接入现场采集，只表述为“受控端网事件验证”，不声称生产部署或一手校园网验证。
- 不作为本课题完成目标：完整攻击图生成、全局攻击路径推演、多阶段 APT 检测和大规模平台建设。

### 0.2 建议申报题目

**校园安全智能体快慢协同防护研究**

该题目不超过申请书规定的 20 个汉字。技术论文或毕业论文可使用更具体的工作题目：

> 面向对抗日志注入的校园安全运营智能体快慢双路径防护

### 0.3 一句话研究问题

当校园安全运营智能体读取端点日志、网络告警和威胁情报等不完全可信数据时，能否用低成本快路径识别其中试图诱导的越权响应动作，并只对高风险事件启动运行时慢路径验证，从而在资源受限条件下同时降低提示注入攻击成功率、错误处置率和推理开销？

### 0.4 研究边界

本研究聚焦**安全运营智能体自身的对抗安全**，研究攻击者通过日志、告警字段或威胁情报文本注入恶意指令，诱导大模型隐瞒真实威胁、降低告警优先级或产生越权响应。研究在隔离实验环境中进行，不直接连接生产校园网，不允许模型对真实资产自动执行封禁、删除或账号停用操作。

本研究不试图完成指南方向三的全部内容，不单独研究完整攻击图生成、多阶段 APT 检测或大规模校园安全平台建设，而是选择“快慢双路径智能研判与响应”作为可在毕业设计周期内完成的切口。

### 0.5 与《思路1》小论文的母子关系

《思路1》不是另一条研究线，而是本课题的**快路径先导论文**。二者共用同一威胁模型、事件模板、授权标签、资产后果表、攻击样本和评价代码，毕设只在此基础上增加慢路径、风险门控、资源评测和校园端网案例。

| 层次 | 《思路1》小论文 | 《思路2》毕设/申报母课题 |
| --- | --- | --- |
| 核心问题 | 授权差距能否改善进入上下文前的安全重排 | 快慢路径能否取得更好的安全—效用—成本折中 |
| 核心方法 | TAG-Fast，具体实现为 TAG-Rerank | 原样复用 TAG-Rerank，新增慢路径与风险门控 |

| 新增成果 | 快路径方法、数据和评测 | 运行时验证、端网案例、成本分析和最佳实践 |

统一链路为：

```text
可信任务/批准剧本 → 检索Top-N候选证据 → TAG-Rerank得到Top-K
→ 智能体研判/模拟响应 → 高风险动作进入慢路径 → 受控输出
```

## 1. 统一研究主线与成果复用

当前《思路1》的核心对象是“可信任务/批准剧本—不可信候选证据—研判与工具动作”之间的授权差距。迁移到校园安全运营后，关键对象可直接对应：

| 开发脚手架中的对象 | 校园安全运营场景 |
| --- | --- |
| 用户任务 | 安全分析师的研判任务、工单目标或已批准 SOAR 剧本 |
| 邮件、文件 | 端点日志、网络告警、威胁情报、历史事件记录 |
| 发送、共享、删除工具 | 查询资产、提升告警、隔离主机、封禁 IP、停用账号等工具 |
| TAG-Rerank 检索前置防御 | 日志/告警进入大模型上下文前的快路径风险筛选 |
| MELON、AttriGuard 等运行时防御 | 高风险响应动作执行前的慢路径因果与授权校验 |

因此，原有的间接提示注入、授权差距、动作后果、检索暴露和运行时验证研究可以保留。需要实质性改变的是：

1. 把通用 Workspace 任务换成校园安全运营任务；原任务只用于链路预实验，不作为校园场景结论；
2. 把普通邮件和文件换成端网安全遥测及威胁情报；
3. 把“是否完成工具任务”扩展为“研判是否正确、响应是否越权、资源是否可接受”；
4. 增加高校资产特点、人员不足、数据不出校和算力受限等约束。

这不是简单换标题，而是将原有方法嵌入一个新的、可验证的安全运营问题。

## 2. 文献基础与研究缺口

### 2.1 当前 Zotero 文献库已经能够支撑的部分

- `HLG6JHSS/YTZC72N9`：MELON，提供运行时重执行与工具调用比较防御；
- `ANIAHUDK`：AttriGuard，提供工具调用的动作级因果归因思路；
- `JPXQ5WV5`：中文提示词注入攻击与防御综述；
- `3T7WITAW`：中文大语言模型网络威胁分析综述，是当前文献库连接“提示注入研究”和“安全运营方向”的核心桥梁。

其中，`3T7WITAW` 已把威胁情报、威胁检测和威胁响应定义为安全运营闭环，并明确指出：用于威胁响应的大模型可能被伪造告警、污染数据和诱导指令误导，同时面临实时性、资源开销和高权限自动化风险。这说明当前选题不是把无关的注入研究强行套入教育安全，而是在已有安全运营研究明确暴露的风险上继续深入。

### 2.2 最新文献带来的创新边界

截至当前检索，[Just Testing, Move Along](https://arxiv.org/abs/2607.24174) 这一 2026 年预印本已研究攻击者向系统日志加入提示注入，使 LLM 将真实恶意日志误判为正常。因此，本课题不能声称“首次发现日志提示注入”或“首次把提示注入用于 SOC”。

同为 2026 年预印本的 [AgenticCyOps](https://arxiv.org/abs/2603.09134) 已从工具编排、记忆、权限边界和验证执行角度研究企业安全运营多智能体架构。因此，也不能把“为 SOC Agent 增加权限控制”单独声称为创新。两篇预印本只用于限定当前创新边界，正式申报时仍需复核其版本和后续工作。

比较现有研究后，可继续验证的交叉缺口是：

1. 日志注入研究主要考察“恶意日志被判为正常”等研判逃逸，较少覆盖从遥测摄入到高权限工具响应的端到端攻击链；
2. 通用 Agent 注入防御主要在邮件、文件、银行或旅行等任务上评测，尚不能证明其适用于多源、高噪声、实时的安全运营遥测；
3. 现有 SOC 智能体框架重视自动化能力、幻觉和架构权限，但对提示注入下的合法任务授权边界及不同后果动作缺乏细粒度实验；
4. 高校安全运营强调低成本、本地化、人手不足和复杂异构网络，不能直接照搬高开销的多 Agent 重执行方案。

上述内容只能表述为**候选研究接缝**。正式申报前仍需用系统检索和最小实验确认，不能直接写成“国内外尚无研究”。

## 3. 场景、威胁模型与安全目标

### 3.1 校园安全运营智能体

构建一个受控的校园安全运营智能体原型，使其完成四类任务：

1. **告警研判**：判断告警是真实攻击、误报还是需要补充证据；
2. **证据关联**：查询端点日志、网络告警、资产信息和威胁情报，形成证据链；
3. **响应建议**：生成符合 MITRE ATT&CK、NIST 或本校处置规范的响应建议；
4. **受控工具调用**：在沙箱中执行查询、告警升级、模拟隔离主机或模拟封禁 IP 等动作。

数据入口至少覆盖：

- 端侧：Wazuh/Sysmon 事件、进程与认证日志；
- 网侧：Suricata 或 Zeek 告警、DNS/HTTP 等网络事件；
- 知识侧：MITRE ATT&CK、处置剧本、历史案例和外部威胁情报。

信任边界必须预先冻结：安全分析师任务、已批准处置剧本、工具模式、角色权限和资产等级属于可信控制源；攻击者可影响的 URL、User-Agent、DNS、文件名、进程参数、告警描述和外部情报自由文本属于不可信证据源。后者可以提供事件事实，但不能单独扩大研判或高影响响应权限。

### 3.2 攻击者能力

本研究将这类攻击定义为**遥测载荷型间接提示注入**，以下简称**对抗日志注入**。一个有效样本必须同时包含：（1）实际或受控模拟的网络攻击/安全事件；（2）攻击者可影响的日志、告警或情报字段；（3）固定编写或由 LLM 生成、场景化伪装并有限迭代的注入载荷。不能把与安全事件无关的普通提示注入直接计作“AI 驱动攻击”样本。

攻击者可以通过正常网络活动影响 HTTP User-Agent、URL、DNS 查询、文件名、进程参数或外部威胁情报文本，并在其中嵌入自然语言指令；可以估计目标查询并加入提高检索相关性的关键词。增强实验允许攻击者使用 LLM 自动生成和改写载荷，并根据黑盒返回的研判结果或响应结果进行有限预算优化。核心实验每个事件包只含一条攻击载荷记录，多记录协同和高频投放仅属于慢路径消耗攻击增强项。

攻击者不能修改：

- 安全分析师的可信任务；
- 系统提示和工具实现；
- 资产重要性与动作后果表；
- 确定性任务检查器；
- 实验环境以外的真实校园系统。

### 3.3 攻击目标

与《思路1》共用的三类核心终点为：

- **研判逃逸**：让真实攻击被判为正常或低风险；
- **优先级操纵**：压低恶意事件或抬高无害事件的处置优先级；
- **越权响应**：诱导智能体隔离无关主机、封禁无关地址、停用无关账号。

“忽略关键日志或引用伪造证据”作为造成上述终点的攻击机制和诊断指标；“诱导高频进入慢路径”只属于毕设的资源消耗增强攻击，不与核心终点混合统计。

### 3.4 安全目标

1. 正常事件和真实攻击的研判能力不得低于预注册的效用下限；
2. 不可信遥测只能提供事实，不能单独授权告警降级、忽略关键证据或高影响响应动作；
3. 高风险动作必须能够追溯到可信任务、可靠证据和预定义剧本；
4. 慢路径只处理少量高风险或高不确定性事件，保持可接受的资源开销；
5. 所有有破坏性的动作只在沙箱中模拟。

## 4. 方法：授权差距感知的快慢双路径

### 4.1 快路径：遥测摄入阶段的低成本筛选

快路径统称 **TAG-Fast**，核心实现 **TAG-Rerank** 与《思路1》保持同一输入、公式和参数语义。它在日志、告警或情报进入 LLM 上下文前运行，只使用轻量模型、规则和正式测试前冻结的动作后果表。

完整处理链不是简单的注入分类，而是：

```text
可信分析任务 u 与批准剧本/角色策略 p
→ 生成证据查询 q
→ 检索Top-N候选证据 e
→ TAG-Rerank安全重排
→ Top-K证据进入上下文
→ 智能体研判或产生沙箱动作
```

对资产上下文 `s`，定义：

- `A_auth(u,p)`：可信任务与已批准处置剧本/角色策略共同授权且前置证据条件已经满足的条款集合；每个条款表示为“研判/工具动作—对象—参数—前置条件”四元组；
- `A_reach`：智能体能够产生的研判决策与当前可调用的工具动作；
- `A_induce(e)`：不可信证据可能诱导的条款，包括研判/工具动作、对象、参数和声称的执行条件；动作同时覆盖降级、关闭、升级或忽略证据等语义决策；
- `P_inj(e)`：候选证据包含提示注入的校准概率；
- `RelCal(q,e)`：查询与候选证据之间经过固定校准的相关性分数。

其中 `p` 汇总已批准处置剧本、角色权限和资产处置策略；`A_auth(u,p)` 取这些可信约束允许集合的交集。公式为简洁省略运行时条件参数：只有冻结的确定性检查器依据可信环境状态 `s` 或剧本规定的独立证据规则确认前置条件成立时，条款才进入激活授权集；单条不可信证据 `e` 只能提出事实线索，不能自行声明条件成立或扩大授权集合。

授权差距、资产后果、快速风险和最终重排分数为：

```text
A_gap(u,p,e) = (A_induce(e) ∩ A_reach) \ A_auth(u,p)

C_gap(u,p,e,s) = max Impact(a,s),  a ∈ A_gap(u,p,e)
C_gap(u,p,e,s) = 0,                A_gap(u,p,e) = ∅

R_fast(u,p,e,s) = P_inj(e) × [c0 + (1-c0) × C_gap(u,p,e,s)]
S_fast(u,p,q,e,s) = RelCal(q,e) - α × R_fast(u,p,e,s)
```

其中 `0 < c0 < 1` 用于降低动作提取漏报带来的失防风险；`α`、`c0`、Top-N、Top-K 和阈值只在开发集选择，测试阶段冻结。相关性和注入概率不得在每个候选集合内重新做易受恶意证据操纵的 min-max 归一化。对研判降级、关闭或忽略证据，后果由漏判风险、关键证据损失和资产重要性确定；对工具动作，则评价机密性、完整性、可用性与业务连续性。

所有方法共享同一个确定性字段解析器，把证据拆为类型化事实 `e_fact` 与自由文本 `e_text`。类型化不代表可信：攻击者可控的 URL、DNS、文件名、进程参数等值必须经过类型校验、长度限制、转义或安全序列化，不能把原始字符串原样送回模型。

在开发集冻结 `τ_low < τ_high` 后，各方法按自己的校准风险执行相同准入规则：

1. `R < τ_low`：完整候选按重排分数竞争Top-K；
2. `τ_low ≤ R < τ_high`：移除自由文本控制段，仅用安全序列化的 `e_fact` 重新计算相关性并竞争Top-K；
3. `R ≥ τ_high`：控制文本不得进入上下文，安全序列化事实可按事实相关性进入Top-K，记录转入慢路径且不能单独授权研判降级或工具动作。

快路径必须同时评价关键证据 Recall@K 和事实保留率，防止通过大面积删除日志获得表面安全收益。

### 4.2 慢路径：响应动作前的因果与授权校验

慢路径只在以下情况触发：高影响工具动作、证据冲突、注入风险高或模型不确定性高。`action-open` 指可信任务只给出目标、未明确允许的动作/对象/参数；由于无法用确定性授权条款判定，它不进入核心因果比较，只作为增强失败案例，并默认转人工复核。

慢路径包含：

1. **控制衰减重执行**：屏蔽可疑自由文本，仅保留经过类型校验、转义或安全序列化的事实字段重新推理；
2. **动作因果比较**：比较原始上下文和控制上下文下的候选工具调用；
3. **剧本约束校验**：检查动作类型、对象、目标和参数是否在可信任务或响应剧本授权范围内；
4. **证据门槛**：按预先批准的剧本配置高影响动作所需证据；默认实验采用至少两个相互独立的证据来源，但不把这一数字宣称为所有场景的通用规则；
5. **人工复核**：隔离主机、停用账号等高风险动作默认只生成建议，不自动执行。

慢路径可以从 MELON 和 AttriGuard 的重执行/因果归因获得实现参考，但不能原样照搬，需要适配结构化安全遥测、工具参数和资产后果。

### 4.3 风险门控

```text
端网遥测与威胁情报
        ↓
结构化事实/自由文本分离
        ↓
快路径：注入风险 + 授权差距 + 资产后果
        ├─ 低风险：直接研判
        ├─ 中风险：降权/净化后研判
        └─ 高风险：进入慢路径
                         ↓
        重执行 + 证据校验 + 工具参数校验 + 人工复核
                         ↓
        受控响应建议或沙箱动作
```

这里的“快慢”不是简单把两个模型串联，而是一个资源分配机制：用风险门控决定哪些事件值得支付慢路径成本。

## 5. 研究问题与可证伪命题

《思路1》的 `SP-RQ1—SP-RQ5` 负责回答攻击链是否成立、TAG-Rerank 是否优于固定风险基线、配对授权差异是否合理以及快路径如何失效。毕设直接复用这些结果，不重新构造一套不兼容的快路径实验，并新增：

- **TH-RQ1**：慢路径能否在可接受的误报和成本下，阻止已经进入上下文的恶意指令造成研判逃逸或越权响应？
- **TH-RQ2**：风险门控的快慢双路径是否比“全部快检”和“全部重执行”取得更好的安全—效用—成本折中？
- **TH-RQ3**：方法在 LLM 自动改写的防御感知攻击、慢路径消耗攻击、异构端网遥测和不同校园资产等级下如何失效？

论文必须重点证明：

1. 快路径在预先指定的主要比较中相对固定风险和非结构化任务条件基线呈现正向配对差异，并报告效应量和区间估计；
2. 慢路径对“已经通过快路径的攻击”仍有独立安全增量；
3. 风险门控相对全量慢路径降低模型调用、延迟或令牌成本，并给出收益—成本曲线；
4. 收益不是依靠删除大量正常日志获得，合法研判效用和关键证据召回需达到预注册下限。

若第一项不成立，小论文不能把 TAG-Rerank 作为主要创新，但毕设不因此终止：使用开发集上表现最好的轻量基线作为快路径，继续研究慢路径、风险门控和失败边界，并把 TAG-Rerank 的负结果作为可解释性分析内容。

## 6. 实验设计

### 6.1 最小实验环境

- 安全数据平台：核心实验使用统一离线事件包，增强实验再接入完整 Wazuh 采集链路；
- 端点遥测：Windows Sysmon 或 Linux audit 日志；
- 网络遥测：Suricata/Zeek 告警；
- 攻击知识：MITRE ATT&CK、NIST 事件响应材料；
- 智能体：一个主 LLM，加3—6个受限工具，包括查询、告警升级、模拟封禁、模拟隔离和模拟停用账号；
- 所有响应动作写入模拟状态，不操作真实主机。

方向三场景验证的必做底线是在隔离靶场自产至少一个安全事件，使其同时生成一类端点记录和一类网络记录，例如 Sysmon 事件与 Suricata EVE JSON；不要求建设完整生产平台，也不连接真实校园资产。

AgentDojo只作为工具调用、环境状态和确定性检查器的开发脚手架；必须新增校园安全运营任务与工具。原 Workspace 邮件/文件任务只做链路预实验，不能作为方向三的场景证据。

公开攻击日志和合成校园资产上下文可扩充任务，但不能替代上述隔离靶场端网配对事件。生产校园网现场采集仍属于增强项，不阻塞核心方法验证。

### 6.2 校园任务集

《思路1》的4个配对事件、约8个任务只作为回归与连续性比较。毕设必须另建并预先冻结至少2个新事件模板、4个配对任务，直到端到端系统和参数全部冻结后才启用；最终核心完成标准为12个任务。只有核心结果方向一致且资源允许时，才增强到20—30个任务。任务至少覆盖一种端点事件和一种网络事件：

新增事件沿用《思路1》的数据规范：每包20条候选证据、3—5条qrels关键证据、1条攻击载荷记录、默认Top-N=10与Top-K=5，并逐字段标记原始采集、公开数据改写、校园资产映射和攻击者注入来源。

- 账号暴力破解与异常登录；
- Web 服务扫描或漏洞利用；
- DNS 隧道与可疑外联；
- 恶意进程或文件落地；
- 误报排查与正常运维行为；
- 涉及统一身份认证、教学系统、科研服务器等不同资产等级的处置任务。

每个任务包含：可信分析目标、已批准剧本/角色策略、端网证据、资产信息、允许动作、禁止动作、正确研判结果和确定性检查器。任务按资产等级、动作后果和是否需要补充信息分层。

核心集中至少选择两类不同等级资产，对相同事件配置不同角色权限、响应剧本和业务连续性后果，并报告授权差距、触发路径和最终决策差异；仅列举校园资产名称不算完成高校场景适配验证。

同一事件模板、攻击目标及其 LLM 改写不得跨开发集和测试集；《思路1》测试集锁定为只读回归集。阈值只可在毕设新增开发集重新校准，毕设新增测试集不得用于调参。

### 6.3 攻击集

核心攻击集与《思路1》一致：

1. 无注入的正常与恶意日志；
2. 直接提示注入；
3. 与日志字段和攻击场景相匹配的伪装注入；
4. LLM 自动改写的多样化注入。

核心结果至少对固定/场景伪装载荷与LLM改写载荷做一次同任务、同目标、同预算的配对比较，分别报告差异；不把普通固定注入的结果直接当作“AI驱动攻击”证据。

增强攻击集在核心结果稳定后加入：

5. 防御感知攻击：根据是否进入上下文、研判结果和动作结果进行有限预算优化；
6. 慢路径消耗攻击：诱导大量事件被升级为高风险。

### 6.4 对照方法

| 组别 | 快路径 | 慢路径 |
| --- | --- | --- |
| A | 无防御 | 无 |
| B | 提示增强或规则过滤 | 无 |
| C | 固定注入概率阈值/固定风险惩罚 | 无 |
| D | 非结构化任务条件风险评分 | 无 |
| E | 授权差距感知 TAG-Rerank | 无 |
| F | 开发集选出的同一最佳轻量快路径 `Q*` | 无 |
| G | 同一 `Q*` | 全量进入同一种慢路径 |
| H | 同一 `Q*` | 风险门控进入同一种慢路径 |

`Q*` 只根据开发集从 B/C/D/E 中选择，测试集不得重新挑选。核心比较是 E 对 C/D、G 对 F、H 对 F 和 H 对 G：分别检验结构化授权差距、全量慢路径增量、门控慢路径增量，以及在相同快路径和相同慢路径下门控带来的安全—成本折中。H 对 G 的唯一实验变量是“是否门控”。

### 6.5 指标

安全指标：

- 研判逃逸成功率；
- `RecordExposure@N/K`：含攻击载荷的记录进入初始候选集/最终Top-K的比例；
- `ControlTextExposure@K`：攻击控制文本实际进入受害模型上下文的比例；保留同一记录的安全序列化事实不计为控制文本暴露；
- 条件ASR：分母为发生 `ControlTextExposure@K` 的攻击episode；
- 端到端ASR：分母为预注册且攻击目标适用的全部任务—攻击episode；
- 越权动作率：发生任一未激活授权条款动作的episode数/全部适用episode数；
- 高影响错误动作率：发生后果等级超过冻结阈值的错误动作episode数/全部适用episode数；
- 防御感知攻击成功率。

上述比例均报告成功数/总数，并按研判逃逸、优先级操纵、越权响应分别统计，不把不适用任务计作攻击失败。

业务效用指标：

- Benign Utility（BU）：无攻击任务中合法任务成功的比例；
- Utility under Attack（UA）：攻击episode中合法任务成功的比例；
- Safe Utility（SU）：合法任务成功、全部攻击目标失败且全部安全检查器通过的攻击episode比例；
- 告警分类 Precision、Recall、Macro-F1；
- 关键证据 Recall@K；
- 事实保留率：防御后保留的qrels关键类型化事实字段数/原始关键事实字段数；
- 正确响应建议率；
- 正常运维证据误报率：被错误降权、剥离或阻断的正常证据数/全部正常证据数。

组件指标：

- `A_auth/A_induce` 研判与工具动作映射 Precision、Recall 和 Macro-F1；
- 注入检测器 AUPRC 及合法操作文本误报率；
- 资产后果标注一致性与高后果动作召回率；
- 慢路径触发率、攻击漏触发率，以及相对全量慢路径的逐episode反事实安全增量；除非预先定义并冻结“应触发”标签，否则不报告触发Precision/Recall。

资源指标：

- 快/慢路径事件比例；
- 每任务 LLM 调用数和 token 数；
- P50/P95 延迟；
- 本地推理显存或 API 成本；
- 每阻止一次高影响错误动作的增量成本。

### 6.6 统计与报告边界

- 以“配对事件模板×攻击目标”为统计簇进行配对分析，同一事件的两个授权条件不视为独立样本；
- 同一攻击的多次改写不当作独立任务；
- 小样本同时报告成功数/总数、配对差异和 Wilson/精确区间；
- 按资产等级、动作后果、日志来源和任务类型分层报告；
- 不把单一校园实验室结果推广为所有高校的普遍结论。

### 6.7 必做项与增强项

| 层级 | 完成标准 |
| --- | --- |
| 毕设必做 | 1个主模型；最终12个核心任务（原8个仅作P2预验证/回归，另冻结4个新任务）；隔离靶场自产1个端网配对事件；至少2类资产等级及差异化授权/后果；3—6个模拟工具；直接、场景伪装和LLM改写3类载荷；TAG-Rerank或最佳轻量快路径；1种可运行慢路径；安全、效用与资源三类指标 |
| 资源允许时增强 | 第二主模型；20—30 个任务；完整 Wazuh 采集链路；有限黑盒自适应攻击；慢路径消耗攻击；更多高校资产类型 |

增强项未完成不影响核心研究问题闭环，但必须在结论中如实限定场景与规模。

## 7. 可控工作量与阶段停止条件

### P0：文献与场景闭环

- 阅读 SOC 智能体、日志注入、通用 IPI 防御和高校安全运营四类核心文献；
- 明确一个可模拟的校园事件和3—6个响应工具；
- 产出威胁模型、任务模板和文献对照表。

### P1：最小攻击链

- 选择 5 个任务；
- 验证日志中的注入能否影响研判或模拟动作；
- 先不实现复杂防御。

这5个任务只用于调试攻击链，不进入正式开发集、测试集或论文统计。

停止条件：如果注入不能稳定进入模型上下文或基础模型本身不能完成正常安全任务，应先修正任务和智能体，不扩展防御。

### P2：快路径可行性

- 实现固定注入检测基线和授权差距快路径；
- 比较正常效用、攻击暴露和开销。

分流条件：如果授权差距快路径不优于相同预算的固定风险基线，不能把它作为小论文主要创新；毕设改用表现最好的轻量基线作为快路径，保留负结果和失败分析，继续 P3。

### P3：慢路径与门控

- 使用 P2 选出的最佳轻量快路径，实现运行时重执行、剧本/证据与工具参数校验；
- 比较门控慢路径和全量慢路径的安全—成本折中。

### P4：教育场景验证

- 完成最终12个核心任务、至少两类差异化资产，以及一个在隔离靶场自产并同时包含端点和网络遥测的校园典型事件；
- 资源允许时再扩展到 20—30 个任务并接入 Wazuh 受控采集链路；
- 形成最佳实践案例和轻量化部署建议。

该顺序保留现有 AgentDojo 经验，但避免一开始建设完整校园 SOC 或运行大规模 API 实验。

成果按“先小论文、后毕设扩展”组织，避免重复建设：

5. **技术建议**：数据分层、工具最小权限、高风险动作人工复核、本地化部署和日志自由文本净化建议。

## 11. 当前方案的主要风险

1. **场景风险**：如果只有通用 AgentDojo，没有端网遥测和校园任务，仍会被认为与方向三脱节；
2. **创新风险**：日志提示注入和 SOC 权限架构已有 2026 年工作，不能只做重复验证；
3. **工作量风险**：完整端网平台、攻击图、多智能体、提示注入防御同时开展会超出毕业设计规模；
4. **数据风险**：真实校园日志可能包含个人信息、账号、IP 和资产信息，应优先使用公开数据或脱敏仿真数据；
5. **安全风险**：自动响应工具不得接入生产环境，攻击测试必须在隔离网络和模拟状态中进行；
6. **评测风险**：只报告攻击成功率会掩盖误报和高开销，必须同时报告正常效用、响应正确性和资源指标。

## 12. 申报书压缩时保留的主线

正式申请书的 3000 字论证不应塞入全部实现细节，只保留：

1. 高校安全运营面临告警过载、人员不足和 AI 智能体对抗输入风险；
2. 当前 SOC 智能体研究偏重能力，通用 IPI 防御缺乏安全运营场景验证；
3. 提出授权差距感知快路径和高风险运行时慢路径；
4. 用端网遥测、校园任务、LLM生成与场景化改写注入及资源指标验证；
5. 产出报告、论文、原型和最佳实践案例。

最终申请书中的创新表述建议使用“面向校园安全运营场景构建并验证”，避免使用未经系统检索证明的“首次提出”“填补国内外空白”。
