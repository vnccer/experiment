# 思路2：校园安全智能体快慢协同防护研究

> 定位：对应指南方向三参考课题2，是立项与毕业设计的母课题。[《思路1》](./思路1.md)作为快路径先导实验，本课题在其基础上增加运行时慢路径、风险门控、端网案例和资源评测。

## 一、背景

### 1.1 为什么做这个

指南方向三关注AI驱动攻击、端网安全遥测、快慢双路径智能决策，以及高校复杂网络中的资源投入、对抗效果和建设模式。本课题选择其中的“资源受限条件下安全运营快慢双路径智能研判与响应机制”作为切口。

校园安全运营面临告警数量大、设备和系统异构、专业人员有限等问题。大模型智能体可以辅助分析日志、关联证据和生成响应建议，但它读取的端点日志、网络告警和外部情报并不完全可信。攻击者可在日志字段中嵌入指令，诱导智能体误判威胁或产生越权响应。

因此，本课题研究的问题是：

> 能否用低成本快路径识别不可信遥测中的高风险控制内容，只对少量高风险事件启动运行时慢路径验证，从而兼顾安全、正常任务效用和资源成本？

### 1.2 之前研究的不足

已有研究分别覆盖日志提示注入、通用Agent防护、安全运营智能体和权限架构，但仍存在以下不足：

1. 日志注入研究多关注分类逃逸，较少验证从遥测摄入到响应动作的端到端后果；
2. 通用Agent防御多在邮件、文件和网页任务上评价，不能直接代表校园安全运营场景；
3. SOC智能体架构强调工具、记忆和权限边界，但缺少“相同证据、不同任务授权和资产后果”的细粒度实验；
4. 全量重执行或多Agent验证成本较高，不适合资源有限的高校场景。

本课题不声称首次发现日志提示注入，也不试图建设完整AI原生SOC，而是聚焦可验证的快慢路径机制。

### 1.3 与思路1的关系

两份思路共用同一套事件、任务、授权标签、攻击样本和检查器：

| 内容 | 思路1：先导论文 | 思路2：立项/毕设 |
| --- | --- | --- |
| 快路径风险判断 | 核心验证 | 直接复用或选择最佳轻量基线 |
| 运行时慢路径 | 不做 | 核心新增 |
| 风险门控 | 只保留接口 | 核心新增 |
| 端网案例 | 离线事件包 | 至少一个受控端网配对事件 |
| 资源评价 | 简单记录 | 比较延迟、调用量和成本 |
| 最佳实践 | 提供素材 | 形成完整案例 |

## 二、创新点

### 2.1 面向校园安全运营的授权建模

把安全分析任务、批准剧本、角色权限、资产等级和工具能力统一纳入授权判断。遥测只能提供事实，不能自行扩大告警降级、封禁、隔离或停用账号等权限。

### 2.2 风险门控的快慢双路径

低风险事件经过快路径后直接研判，中风险事件净化后研判，高风险事件进入慢路径。研究重点不是简单串联两个模型，而是决定哪些事件值得支付额外验证成本。

### 2.3 运行时证据与动作验证

慢路径对高风险结果执行控制衰减重推理、剧本授权检查、证据门槛检查和工具参数检查，阻止已经穿过快路径的攻击造成高影响后果。

### 2.4 安全—效用—成本联合评价

同时比较攻击成功率、越权动作、正常任务效用、关键证据保留、慢路径触发比例、延迟和模型调用成本，避免以删除大量日志或全量重执行换取表面安全。

### 2.5 受控端网案例

在隔离环境中复现至少一个同时产生端点和网络记录的校园典型事件，展示从遥测、AI研判到受控响应的完整链路。其价值在于场景化验证和最佳实践，不声称生产部署。

## 三、实验框架

### 3.1 最小研究对象

- 一个主模型；
- 一类端点遥测，如 Sysmon/Wazuh 风格日志；
- 一类网络遥测，如 Suricata/Zeek 告警；
- 3—4个受控工具，如查询、升级告警、模拟封禁和模拟隔离；
- 最终约12个核心任务，由6个事件模板的不同授权条件组成；
- 至少两类不同重要性的校园资产。

前期先使用离线事件包；完整Wazuh采集链路、第二个模型和更多任务均为增强项。

### 3.2 总体流程

```text
可信任务、批准剧本和角色权限
→ 检索端网证据
→ 快路径：注入风险、授权差距和资产后果
   ├─ 低风险：直接研判
   ├─ 中风险：净化后研判
   └─ 高风险：进入慢路径
→ 慢路径：重推理、证据校验、授权与参数检查
→ 受控响应建议或沙箱动作
→ 检查器评价安全、效用和成本
```

### 3.3 快路径比较

快路径先比较：

1. 无防御；
2. 固定检测或固定风险惩罚；
3. 非结构化任务条件风险评分；
4. 思路1提出的授权感知 TAG-Rerank。

在开发集上选择表现最好的轻量方法作为 `Q*`。如果TAG-Rerank没有优势，仍可使用其他 `Q*` 继续完成慢路径研究。

### 3.4 慢路径与门控比较

使用同一个 `Q*` 和同一种慢路径比较三组：

1. `Q*`，不使用慢路径；
2. `Q*`，所有事件都进入慢路径；
3. `Q*`，仅高风险事件进入慢路径。

这样可以分别回答：慢路径是否带来额外安全收益，以及风险门控能否降低全量慢路径的成本。

### 3.5 攻击与任务

核心攻击包括：

- 直接提示注入；
- 与日志字段和攻击场景匹配的伪装注入；
- 少量LLM自动改写注入。

核心任务包括异常登录、恶意进程、DNS异常、Web攻击或误报排查，并覆盖只读研判与受控响应两类授权条件。

防御感知攻击和诱导大量事件进入慢路径的消耗攻击，只在核心结果稳定后增加。

### 3.6 主要指标

安全：

- 端到端攻击成功率；
- 越权动作率；
- 高影响错误动作率；
- 控制文本进入上下文的比例。

效用：

- 无攻击任务成功率；
- 攻击下合法任务成功率；
- 关键证据 Recall@K；
- 正常证据误报率。

成本：

- 慢路径触发比例；
- 模型调用数和 token 数；
- P50/P95 延迟；
- API或本地推理成本。

### 3.7 执行阶段

1. **P0：场景与文献闭环**。明确一个受控校园事件、可信边界和工具范围；
2. **P1：最小攻击链**。先用少量任务确认正常能力和注入影响，不实现复杂防御；
3. **P2：快路径可行性**。完成思路1的主要比较并选择 `Q*`；
4. **P3：慢路径与门控**。比较无慢路径、全量慢路径和风险门控；
5. **P4：方向三场景验证**。完成约12个任务和一个受控端网配对案例，形成最佳实践。

每一阶段达到停止条件后再扩展，避免一开始建设完整校园SOC。

## 四、细节

### 4.1 信任与授权边界

可信控制源包括：分析师任务、批准剧本、角色权限、工具模式、资产等级和可信环境状态。

不可信证据源包括：日志和告警自由文本、外部情报，以及攻击者可影响的 URL、User-Agent、DNS、文件名和进程参数。

授权条款使用“动作—对象—参数—前置条件”表示。只有可信环境状态或预先规定的独立证据规则能够激活前置条件；单条不可信记录不能自行完成授权。

### 4.2 快路径

快路径沿用思路1的简化逻辑：

```text
风险 = 注入可能性 × 授权差距及资产后果
安全重排分数 = 证据相关性 - 风险惩罚
```

低风险内容完整进入上下文；中风险内容去除可疑控制文本后保留事实；高风险控制文本不得进入模型，并将事件送入慢路径。

### 4.3 慢路径

慢路径最小实现包括：

1. 屏蔽可疑自由文本，仅保留校验和安全序列化后的事实重新推理；
2. 比较原始上下文与净化上下文下的研判或动作差异；
3. 检查动作类型、对象和参数是否符合可信任务与剧本；
4. 高影响动作要求独立证据支持，并默认转为人工复核建议。

只实现这一种可运行慢路径，不同时建设多个Agent或复杂工作流。

### 4.4 数据与实验控制

每个事件模板记录数据来源、关键证据、注入字段、资产等级、允许动作、禁止动作和正确结果。开发集用于选择阈值和 `Q*`，测试集冻结后不得继续调参。

隔离靶场至少自产一个同时产生端点和网络记录的事件。公开日志和仿真数据可以扩展任务，但不能冒充真实校园网一手数据。

### 4.5 最小完成项与增强项

必须完成：

- 约12个核心任务；
- 一个主模型；
- 一个受控端网配对事件；
- 一个可运行快路径和一个可运行慢路径；
- 无慢路径、全量慢路径和风险门控比较；
- 安全、效用和成本三类结果。

资源允许时再增加：第二个模型、更多任务、完整Wazuh链路、防御感知攻击和更多校园资产类型。

不做：全局攻击图、多阶段APT还原、生产自动处置、多智能体平台和大规模校园SOC建设。

### 4.6 风险与备选路线

- 如果基础模型不能完成正常安全任务，先修正任务和智能体；
- 如果日志注入无法影响模型，先检查检索暴露和任务设计；
- 如果TAG-Rerank没有优势，改用最佳轻量基线作为 `Q*`；
- 如果慢路径没有额外安全收益，分析攻击进入点和检查器缺口；
- 如果无法获得生产数据，只做受控端网事件，不声称真实部署；
- 如果时间不足，优先保证12个任务、三组慢路径比较和最佳实践案例。

### 4.7 预期成果

1. 研究报告：校园安全运营智能体对抗日志注入与快慢协同防护；
2. 论文：优先完成思路1快路径论文，再将其作为毕设章节复用；
3. 原型：离线端网事件摄入、风险门控、运行时验证和沙箱动作；
4. 数据与评测：事件模板、注入样本、授权标签和确定性检查器；
5. 最佳实践案例：隔离环境中的端网事件、AI研判和受控响应演示；
6. 技术建议：数据分层、工具最小权限、高风险动作人工复核和资源配置建议。
